# 보드 확인

목표: 값을 최신으로 만들고, 주의할 것과 할 일을 먼저 말한 뒤 카드를 보여 준다.

## 순서

1. `board_evaluate`로 항목 목록과 상태를 본다.
2. **값 갱신**: 상태가 `stale` 또는 `unknown`이거나 갱신 주기가 지난 항목마다
   - 출처(`source`)에 맞는 커넥터·도구가 있으면 그걸로 값을 읽고 `snapshot_record(item_id, value, observed_at, source_ref)`로 기록한다.
     `observed_at`은 그 값이 실제로 측정된 시각, `source_ref`는 어디서 읽었는지(문서 이름, URL 등).
   - 출처가 `manual`이거나 읽을 방법이 없으면 사용자에게 한 줄로 묻는다: "이번 주 운동 몇 번 하셨어요?" 답을 기록한다.
   - 값을 지어내지 않는다. 모르면 비워 둔다. 오래된 값은 카드에서 숫자 대신 "오래됨"으로 보인다.
3. 다시 `board_evaluate`를 부른다.
4. **먼저 말하기**: `alerts`가 있으면 카드보다 먼저 한두 문장으로 말한다. 예: "저축이 경고선 아래입니다(25만 원, 경고 < 30만 원)."
5. **할 일 제안**: `suggested_actions`마다 사용자에게 할 일로 만들지 묻고, 동의하면 `action_add(goal_id, text, item_id, due)`.
   사용자가 다르게 하고 싶다고 하면 그 말로 만든다.
6. `board_get`의 카드를 그대로 보여 준다. 별도 창, 아티팩트, 표로 다시 그리지 않는다.
7. 열린 할 일이 끝났다고 하면 `action_update(action_id, state="done")`. 안 하기로 하면 `"dropped"`.

## 값에 대한 질문

"이건 왜 이래?"라고 물으면 그 항목의 질문·행동 규칙과 최근 값으로 답하고,
사용자가 이유를 말하면 `note_add(item_id, text)`로 남긴다. 다음에 같은 걸 다시 묻지 않게 하기 위해서다.

## 예약 실행일 때

사용자가 보고 있지 않을 수 있다. 값 갱신(2단계의 커넥터 부분)만 하고, `alerts`가 있을 때만 짧게 알린다.
모두 정상이면 카드 한 줄로 끝낸다.
