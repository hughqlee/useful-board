# 목표 인터뷰

목표: 사용자의 말에서 **목표 1개 → 지표 항목 1~3개 → 각 항목의 행동 규칙**까지 끌어내 보드에 넣는다.
대시보드를 꾸미는 일이 아니다. 행동을 바꾸지 못할 항목은 만들지 않는다.

## 원칙

- 한 번에 질문 하나. 사용자가 이미 말한 것은 다시 묻지 않는다.
- 사용자의 표현을 그대로 쓴다. 전문 용어(지표, KPI, 메트릭)를 강요하지 않는다.
- 숫자가 없으면 만들어 주지 않는다. "얼마면 괜찮다고 느끼세요?"처럼 사용자에게서 끌어낸다.
- 보드 전체 항목은 7개까지다. 이미 꽉 찼으면 새 항목을 넣기 전에 뺄 항목을 함께 고른다.

## 순서

1. **목표**: 무엇을 이루고 싶은지, 왜인지, 언제까지인지.
   좋은 목표는 끝이 보인다. "건강해지기"면 "6월까지 10kg 감량"처럼 끝을 같이 정한다.
   → `goal_set(id, title, why, due)`. id는 영어 소문자·하이픈(예: `savings`, `weight-loss`).
2. **질문**: "이 목표가 잘 가고 있는지 매주 무엇을 보면 알 수 있을까요?"
   답을 예/아니오나 숫자로 답할 수 있는 질문으로 다듬는다. 예: "이번 달 저축이 계획대로 가고 있나?"
   목표 하나에 1~3개면 충분하다. 결과(체중)와 그 결과를 만드는 행동(주 3회 운동)을 하나씩 두는 것이 좋다.
3. **값의 출처**: 그 숫자를 어디서 얻는지. 사용자가 쓰는 앱·시트·서비스가 있으면 그것을, 없으면 `manual`(대화에서 직접 말하기).
   단위를 정한다(원, kg, 회, 쪽).
4. **비교 기준**: 목표치(target), 경고선(warn), 직전 기간 비교(vs_previous) 중 최소 하나.
   경고선을 먼저 묻는다: "얼마 아래로 떨어지면 뭔가 해야 한다고 느끼세요?"
   형식은 `">= 420000"`, `"< 300000"`.
5. **행동 규칙**: "경고선을 넘으면 무엇을 하실 건가요?" 구체적인 행동 하나. 예: "20일에 30만 원 미만이면 지출 상위 3개 항목 점검".
   답이 없으면 그 항목은 보드에 둘 이유가 없다고 솔직히 말하고 빼자고 제안한다.
6. **갱신 주기**: 값이 실제로 바뀌는 주기(hourly, daily, weekly, monthly, manual).
7. **검토일**: 기본은 오늘부터 90일 뒤. "이때 이 항목이 아직 쓸모 있는지 다시 보겠습니다"라고 알린다.
8. `item_propose(goal_id, item)`로 넣는다. 거부되면 사유(원칙 번호)를 사용자에게 그대로 전하고 그 부분만 다시 묻는다.
9. 첫 값을 알면 바로 `snapshot_record`로 기록한다(출처는 `source_ref`).
10. 끝나면 `board_get`의 카드를 대화에 그대로 보여 준다. 별도 창이나 아티팩트로 만들지 않는다.

## item 형태

```json
{
  "id": "monthly-saving",
  "question": "이번 달 저축이 계획대로 가고 있나?",
  "metric": { "source": "sheets:가계부/저축", "compute": "sum(this_month)", "unit": "원" },
  "compare": { "target": ">= 420000", "warn": "< 300000" },
  "action_rule": "20일에 30만 원 미만이면 지출 상위 3개 항목 점검",
  "refresh": "daily",
  "review_by": "2027-03-31"
}
```
